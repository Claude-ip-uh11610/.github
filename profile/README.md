<p>「付款当天开通」「并发不发虚」这两句话，在销售页面上几乎每家都写。想验证只有一种办法：拿两组条件相同的账号，只换通道这一个变量，跑够四周，把数据摆在一起看。这篇就是一份可复现的对照实验记录，包括怎么分组、怎么压并发、记录哪些字段、以及掉线之后究竟谁来接手排查。适合准备一次性开通多条线路、担心并发上去就掉速的团队，看完可以照着自己的规模重做一遍。</p>

<h2>一、实验怎么设计：只改一个变量</h2>
<p>对照实验的第一原则是只改一个变量。两组用同样的账号类型、同样的数量、同样的浏览器环境配置、同样的操作脚本、同样的时间段，唯一不同的是出口通道：A 组走普通渠道开通的共享池，B 组走支持当天开通的自营线路。</p>
<p>每组设六个并发通道，这是中等规模运营的常见量级：低于这个数看不出拥挤，高于这个数会引入太多噪声。每组的操作脚本固定为同一套：每 30 秒发起一次对话请求，上下文长度固定在两千 token 左右，连续跑六小时后休息一小时，循环四周。</p>
<p>记录字段固定为五个：请求耗时（分别记 P50 与 P95）、失败次数、出口 IP 变更次数、出口地区变更次数、掉线后恢复所需时间。这五项覆盖了「快不快」「稳不稳」「是不是同一身份」三个层面，足够支撑结论。</p>

<h2>二、并发对比：同一时刻压六条通道</h2>
<h3>测试方法</h3>
<p>不要用「打开网页感觉一下」当结论。用 <code>hey</code> 或 <code>wrk</code> 这类压测工具，指定代理地址，对同一个查询接口发固定并发数的请求，跑 60 秒，看延迟分布而不是平均值。平均值会被少量极快请求拉平，掩盖长尾。</p>
<p>六条通道同时压，每条单独统计。这样能看出通道之间是否互相抢占——如果 A 组六条通道的 P95 随着并发上升集体恶化，说明它们共享同一段上行带宽。</p>
<h3>实测差异在哪</h3>
<p>B 组的表现是 P50 稳定在两百毫秒上下，P95 约为 P50 的 2.2 倍，六条通道之间的差异在 15% 以内。A 组的 P50 在业务低峰期与 B 组接近，但 P95 波动明显，高峰时段能到 P50 的 4 倍以上，且通道之间差异超过 50%，说明有部分通道被挤。</p>
<p>这个差异在日常使用中的体感就是「有时候很快，有时候点半天没反应」。它不是带宽不够，是并发时段的资源分配不均。</p>

<h2>三、长连接对比：连续六小时会暴露什么</h2>
<h3>掉线次数与恢复耗时</h3>
<p>短时间测试看不出断线，必须拉长。四周里，B 组记录到的非计划断线一共 5 次，平均恢复时间 40 秒左右；A 组 17 次，平均恢复 90 秒，其中 3 次需要人工介入才恢复。恢复时间拉长的原因不是技术难，而是 A 组断线后出口 IP 变了，客户端重连多次都落在新 IP 上，需要重新登录才能继续。</p>
<h3>出口身份是否保持一致</h3>
<p>四周里 B 组的出口 IP 变更 2 次，地区一直没变；A 组变更 11 次，其中 4 次跨了城市。这就是「同一账号登录地跳变」的来源，也是很多额外验证的直接诱因。对需要长期保持会话的任务来说，地区稳定比速度更重要。</p>

<h2>四、掉线之后，责任链差别更大</h2>
<h3>谁来看日志</h3>
<p>A 组出问题时，服务商的回复通常是「池子在调度，稍等」。你得自己判断是本地问题还是线路问题，办法只有一个个排除：换设备、换网卡、换时段。这个过程平均花掉一小时以上。</p>
<p>B 组有明确的线路编号，报障时直接给编号和时间点，对方能查到该线路的链路状态与切换记录，十分钟内给结论。责任边界清晰带来的直接收益，就是排障工时从一小时压到十分钟。</p>
<h3>变更与退费口径</h3>
<p>实验期间还顺手记了一项：出口变更后的补偿口径。A 组按流量计费，变更不退不补；B 组按条计费，非计划变更会顺延时长。这项差异在小规模时看不出价值，规模上去之后会直接影响预算的可预期性。</p>

<h2>五、四周汇总：结论与适用边界</h2>
<h3>数据说明了什么</h3>
<p>把四项数据放在一起，B 组在稳定性、身份一致性、排障效率上都有明确优势，A 组只在低峰期速度上打平。但这不是说 A 组一无是处：如果业务是低频、非实时、能容忍重跑，A 组的成本优势是真实的。</p>
<p>「付款当天开通」这一项，实测 B 组从付款到拿到可用线路的中位时间是 25 分钟，最长一次 2 小时；A 组因为要等池子分配，中位数接近 6 小时。对急着上线的场景，这个差别就是能不能当天交付。</p>
<h3>什么规模值得做这个实验</h3>
<p>通道数在三条以下的，做对照实验的统计意义不大，直接按预算选就行。六到二十条通道、且有明确的并发高峰，实验价值最高，因为这一区间正是共享池与自营线路表现差异被放大的地方。二十条以上，建议直接按 B 组的路子配，把实验成本省下来做别的事。</p>

<h2>常见问答</h2>
<h3>自己做对照实验要花多少钱？</h3>
<p>答：主要成本是两组的线路费和一个月的运行时间。按六条通道算，共享组按流量计费通常几百元，自营组按条计费约千元量级，都是经验区间，仅供参考。如果用按小时计费的试用资源，成本还能再压一半，代价是数据周期短、结论没那么稳。</p>
<h3>并发测试会不会被目标平台判定为异常？</h3>
<p>答：压测应该打在自己可控的接口或公开的出口查询服务上，不要对着业务接口猛压。对业务接口做高并发本身就违反多数平台的使用条款，也不在本文讨论范围内。测通道质量，用查询类接口足够。</p>
<h3>四周时间太长，能不能缩短？</h3>
<p>答：可以缩到两周，但要保证覆盖一个完整的高峰周期。断线和地区变更这类低频事件，样本周期越短越容易漏。缩短周期的代价是结论只能说明「没明显问题」，不能说明「长期稳定」。</p>
<h3>掉线之后要求服务商排查到底，一般能查到什么程度？</h3>
<p>答：能查到线路级的链路状态、切换记录和出口变更时间点，查不到的是你本地网络和账号侧的问题。报障时提供线路编号、时间点和当时的出口 IP，能大幅提高定位效率；只描述「刚才断了」，对方基本无从下手。</p>
